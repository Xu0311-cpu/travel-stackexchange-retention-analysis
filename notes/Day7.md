# Day7 – Travel 定点验证：该不该推 comment？

## 1. 今天要回答的问题
在 Day5/Day6 我们得到一个方向性判断：行为效果依赖场景（community），因此我曾倾向在 travel 社区优先推动 comment，借助互动形成“内容供给→互动→回访”的正循环。

Day7 的目标是**只看 travel 社区**，回答两个更现实的问题：
1) travel 里 comment/post 的样本规模（base）是否足够支撑策略判断？  
2) 如果样本太小，我们应该怎么做，避免被“噪音”误导？

---

## 2. 指标口径（我今天用什么算的）
- **base**：当天在 travel 社区做某个 action 的独立用户数  
- **returned**：这些 base 用户中，次日仍出现在 travel（任意行为）的用户数  
- **D1 retention（日级）**：returned / base（逐天计算）  
- **Aggregated D1（更稳定）**：所有天的 returned 总和 / base 总和（把每天加总后再算比例）

> 解释：当 base 很小（比如 1–3 人）时，日级 D1 的比例会被“个别用户回不回来”强烈影响，因此 Aggregated D1 更适合作为稳定参考。

## 4. 我看到的关键现象（用人话解释）
### 现象 A：post 的 agg_d1 看起来最高，但完全不稳健
- post 的 `total_base=11`，`median_base=1`，说明几乎每天只有 1–3 个用户产生 post。
- `std_d1=0.452` 极高，意味着日级 D1 波动巨大。
- 这种情况下，哪怕“多 1 个人回访”，比例都会被显著放大。

**结论（暂定）：**
post 的“高留存”更可能是**小样本比例被放大**，不能作为“推 post 会提升留存”的依据。

---

### 现象 B：comment 是合理的互动方向，但目前样本也偏小
- comment 的 `total_base=41`，比 post 大很多，但 `median_base=2`，仍然属于长期小 base。
- `days_base_lt10=15`（几乎每一天都<10）说明样本规模仍不足以支撑强结论。
- `std_d1=0.256` 仍然不小，提示波动风险存在。

**结论（暂定）：**
“在 travel 推 comment”作为机制假设是合理的，但目前数据只能支持“可能”，不足以支撑“应该重押”。

---

### 现象 C：view 是当前 travel 中最稳定的入口信号
- view 的 `total_base=141` 最大，且 `std_d1=0.136` 相对更小（更稳定）。
- 虽然 agg_d1 并不最高，但它是当前 travel 中**样本更充足、波动更可控**的一类行为。

**结论（暂定）：**
如果要做验证或运营实验，应优先把“入口人群”建立在 view 上，否则极易被小样本噪音误导。

---

## 5. 当前结论（必须用“可能/更可能”，不下因果）
1) travel 里 post/comment 的 base 长期偏小，因此它们对应的留存比例更容易被个别用户行为放大。  
2) post 的高 agg_d1 更可能是**小样本假高**；comment 的表现较中性，但同样受样本规模限制。  
3) 如果要把“推 comment”变成可验证策略，应该先在更稳定的入口（view 人群）上建立对照验证，而不是直接依据现有比例下结论。

---

## 6. 运营建议（今天能落地的版本）
- **不建议**直接把“推 comment 提升留存”当成确定策略重押（样本不足、波动偏大、容易造成垃圾互动）。
- **建议**采用“先稳定入口→再验证互动”的路径：
  1) 以 travel 的 view 人群作为稳定入口（样本更大，波动更小）  
  2) 在 view 场景中做轻量 comment 引导（例如：评论入口更显眼、评论提示、优质评论示例/置顶）  
  3) 用“同社区次日回访”作为短期指标，并额外关注垃圾互动风险（短评论、重复评论等代理指标）
